# 0.6.0 pre-release review: remaining findings

Status: **triage record.** A seven-reviewer sweep of `dev/0.6.0` (2026-07-30)
found a set of release blockers, all of which were fixed on the branch (see
the `fix:` commits between `4843967` and the branch tip). This file records
everything that was found and deliberately **not** fixed before release, so
the findings are not lost. Items are grouped by how they should be treated.

Guiding decisions made at triage time:

- Migration/legacy corner cases were deprioritized: the 0.5-to-0.6 migration
  has few users, and `aivm/legacy/pre_0_6_0/` is scheduled for deletion once
  the fleet is on 0.6 stores. Its bugs are documented here rather than fixed.
- The bar for the new (0.6) protocol was "stable and robust"; those bugs were
  fixed, not deferred.

## 1. Known migration/legacy defects (documented, not fixed)

These all live in `aivm/legacy/pre_0_6_0/` and die with it.

### 1.1 Symlinked `$HOME` permanently disables rollback, resume, and verify

Apply normalizes backup targets with `resolve()`
(`migration_apply.py` `_backup_candidates`), while rollback authorization
(`_frozen_backup_candidates`) and journal rebuilding use `_lexical_absolute()`
(no symlink resolution). On hosts where a home path traverses a symlink
(Fedora Silverblue `/home -> /var/home`, NFS automounts), apply completes but
rollback then fails with *"Protected backup manifest names an unauthorized
target"* and resume/verify fail with *"Released inputs or planner output
changed"*. Fail-closed (backups intact under the transaction dir; recovery is
manual), but the advertised safety net does not exist on such hosts.
Reproduced empirically. Structural fix: one backup-target enumeration with one
normalization policy shared by apply and rollback (also removes ~80 duplicated
lines).

### 1.2 No binding between the reviewed plan and the applied plan

`aivm config migrate apply` rebuilds a fresh plan and applies it; nothing ties
it to the `migrate plan` output the user reviewed, and the approval prompt
shows only a static purpose paragraph. Inputs edited between plan and apply
migrate silently. Intra-invocation binding (source hashes re-verified under
lock) is solid. Fix shape: print the plan summary + sha before approval, or
accept `--plan-sha`.

### 1.3 Control-state trust checks guard rollback only

`_validate_transaction_control_paths` (ownership/symlink/mode validation of
`state.json`/`plan.json`) runs only on rollback. `resume`, `verify`, and the
resumed-apply branch read the same files unchecked, and root resuming an
unprivileged user's transaction is a designed path (`_write_profiles` directs
users to re-run with sudo). A crafted journal in a user-owned transaction dir
can steer root's profile writes (content bounded to profile fields). The
rollback code names this exact asymmetry as a security invariant; the other
entry points should call the same validator.

### 1.4 Rollback's displaced-cleanup failure un-does a verified restore

After the backup is restored and digest-verified, a failure while removing
the displaced migration output (`_remove_path(displaced)`, EBUSY/EIO window)
deletes the verified restore, renames the partially deleted displaced tree
back, and wedges every retry on *"Rollback target changed after migration
wrote it"*. Once the restore is verified, a displaced-cleanup failure should
report the leftover path and count the rollback as done.

### 1.5 Legacy-store deletion journal can wedge a VM name

Non-machine scope only: a crash between the final `save_store` (VM record
removed) and `store-finalized` leaves an `active` journal that
`complete_missing_vm_deletion` cannot resume (machine-scope-only) while
`require_vm_creation_not_blocked` keeps refusing the name. Recovery is manual
journal deletion.

### 1.6 Smaller migration items

- Nothing at plan time asserts `base_dir` does not overlap the migrated
  trees; mount safety is by layout convention plus the per-target digest
  gates.
- `_freeze_expected` writes `expected/` artifacts nothing reads (~55 dead
  lines) — either verify against them or drop them.
- `_file_sha256` is duplicated verbatim between `migration.py` and
  `migration_apply.py`; a redundant in-loop import of
  `bootstrap_identity_paths` shadows the module-level one.

## 2. Minor defects in current code (fix opportunistically)

- **Ambiguous provider publish failures are flattened**
  (`credentials/service.py` ~321-343): a timeout/5xx during key publish with
  no recorded `provider_key_id` becomes `provider_managed=False`, and revoke
  then refuses with *"AIVM never registered credential…"*, which misstates
  what is known. Re-running `creds add` re-adopts by fingerprint, but the
  remedy is undiscoverable from the message.
- **Guest verification failures masquerade as provider lag**
  (`credentials/service.py` ~214-229): exit 78 (managed git rewrite
  missing/drifted) and SSH transport failures are all reported as "provider
  has not accepted the public key" and the grant returns success.
- **`keys.py` ~359 recheck runs before creation**: inside a plan scope the
  "recheck the descendant chain immediately before writing key material" call
  executes at submission time, while the mkdirs are still queued — it
  validates nothing for fresh directories. Not exploitable
  (`inspect_host_keypair` re-validates after the flush), but the code asserts
  a property it does not provide.
- **Adopting a legacy `''`-owned attachment record in a machine store
  duplicates it** (`attachments/resolve.py` ~295 vs `_record_attachment`
  upsert keyed on `(host_path, vm_name, owner)`), after which every resolve
  of that folder fails on "Multiple attachments…". Requires a hand-edited
  store today; the adopt path should rewrite the record's owner in place.
- **Error messages promising flags that don't work**: detach ambiguity says
  "Retry with `--owner_principal`" but that flag alone raises without
  `--admin_override`; the foreign-owner refusal points `aivm code`/`aivm ssh`
  users at an `--admin_override` flag those commands don't have; a stale
  `NotImplementedError` message in `attachments/resolve.py` claims read-only
  is only for shared/shared-root (persistent RO now exists; only git lacks
  it).
- **`vm_connect._start_remote_tunnel_session` claims `user_driven=True`**
  for a scripted non-TTY guest mutation (tmux + `code tunnel`), which fails
  the documented bar for the exemption (terminal handed over, aivm performs
  no write). Bounded impact; should confirm like any other modify.
- **`enrollment.bootstrap_identity_paths` derives `use_sudo` from the env
  var** independently of the `layout` parameter it was given; a
  caller-supplied layout can disagree with the sudo decision.
- **Interrupted `_stage_split_transaction`** (before the `os.replace`)
  leaves `.aivm-store-transaction-*` temp dirs behind forever; recovery
  prunes only completed markers.
- **`machine_store_policy(group_gid=None)`** resolves `DEFAULT_MACHINE_GROUP`
  and ignores `AIVM_MACHINE_GROUP` (latent — current callers all pass a gid).
- **Explicit `--config /var/lib/aivm/<other>.toml`** gets legacy routing
  semantics but the machine io-policy and the shared `store.lock`
  (`io._resolve_io_policy`), a surprising hybrid.
- **`config_store/parse.py` raises bare `ValueError`/`TypeError`** for
  malformed documents (duplicate VM names, bad integers), which reach users
  as tracebacks; the `[tools]` cases were converted to AIVMError this
  release, the rest of the parser should follow the same pattern.
- **Credential audit-boundary docstring** (`credentials/__init__.py` ~18)
  names `cli.vm_lifecycle` as a guards importer; the actual importers are
  `vm/deletion.py` and `vm/create.py`.

## 3. Refactor opportunities (quality, no behavior change)

Duplication that already caused bugs (highest value):

- `credentials/guest.py _validated_entry_repository` vs
  `credentials/service.py entry_repository` — the pair whose drift caused the
  principal-scoped credential blocker. Collapse to one function.
- GitHub vs GitLab provider-key selection: `github.py` ~307-389 duplicates
  `providers.py` ~220-307 nearly token-for-token (~65 lines); route GitHub
  through the parameterized copy.
- Owner-resolution ladder duplicated between `attachments/resolve.py`
  (~239-294) and `cli/vm_attach.py` detach (~760-812) with divergent error
  messages (source of the `--owner_principal` message bug).

Dead code:

- `attachments/ownership.py validate_attachment_owner` — zero callers; the
  dangling-owner rejection it promises is never enforced. Wire into store
  lint or delete.
- `credentials/gitlab.py update_deploy_key` — only its own unit test calls
  it.
- `profile_store.profile_debug_json` — no callers.
- `config_store/resolve.py find_principal_for_host` — used only by tests.
- `config_store/io._StoreLock` — trivial pass-through over
  `ExclusiveFileLock`.

Triplicated helpers (one shared home each):

- `_toml_escape`: `config.py`, `config_store/render.py`, `profile_store.py`.
- Machine-lock scope wrappers: `_PersistentManifestLock` (manifest.py),
  `_DetachLockScope` (vm_attach.py), `_DeletionLockScope` (deletion.py).
- Collision-resistant stem sanitizers: `machine_store._resource_stem`,
  `enrollment._storage_stem` (byte-identical), `io._safe_fragment_stem`.
- Fail-closed `env LC_ALL=C stat` probes: `deletion._path_exists`,
  `domain._host_path_exists`, inline in `_assert_no_mounts_below`.
- `_fsync_dir`: `config_store/io.py` and `profile_store.py`;
  `save_user_profile` re-implements `_atomic_write_text` and could be a
  `StoreFilesystemPolicy(0o600/0o700)` over the shared primitive.

Other:

- `credentials/service.py` revoke (~643) vs abandon (~744) repeat the
  "reconcile guest, remove host key, remove record, save" block; one helper
  keeps the two cleanup orders provably identical.
- `_write_abandon_tombstone` skips the symlink/ownership validation every
  other credential path gets (hardening, same-user surface).
- `transport._run_guest_root_script(check=False)` still raises (RuntimeError
  instead of CommandError), making the manual `code != 0` re-checks in
  `persistent/replay.py` dead; the
  `int(getattr(result, 'code', getattr(result, 'returncode', 0)))`
  duck-typing incantation appears 6+ times across
  transport/replay/manifest.
- Double manifest sync under lock on the attach and detach paths
  (`vm_attach.py` ~443 then `host_bind.py` ~74; same in detach) — idempotent
  but obscures the real write point.
- `render_store_networks_toml` duplicates the `[[networks]]` emission block
  inside `render_store_toml` — extract `_emit_network`.
- `render_user_profile`/`parse_user_profile` name each `BehaviorConfig`
  field by hand; a `__dataclass_fields__`-driven emitter removes the
  "new behavior field silently dropped on profile rewrite" trap.
- `scoped_store._read_public_key` duplicates `init._read_public_key_text`;
  `_join_existing_machine` hand-copies the field list of
  `materialize_machine_cfg`.
- `guest_tools._guest_tool_*`/`_guest_ensure_*` compat shims (~478-543) have
  no consumers outside `vm/lifecycle.py`'s re-export list; retire.
- Enrollment/access bootstrap ssh plumbing: `enrollment.py` ~456-467 and
  `access_control.py` ~224-248 build the same forced-key ssh command and
  repeat `_effective_cfg`/IP resolution; one helper keeps the ssh hardening
  options and CommandControlError-sensitive error mapping in one place.
- `setup.py` twin report dataclasses and `vm_creds.py` twin print functions
  are parallel GitHub/GitLab structures with mostly shared fields.
- Unpinned-locale virsh parse sites outside the fixed paths (same
  `pin_locale` fix applies): `vm/drift.py read_actual_vm_hardware`,
  `vm/update/detect.py`, `vm/connectivity.py`, `attachments/session.py`,
  `vm/share.py` domstate probes, `cli/config/discover.py`, and the domstate
  poll in `vm/create.py`.

## 4. Release-process notes

- **`uv.lock` is stale and pins an internal mirror**: its `requires-dist`
  lacks the docs/tests deps this branch added, and every registry URL points
  at an internal artifactory hostname (pre-existing on main). Regenerate
  against public PyPI before tagging, or drop the lock from the repo.
- **CHANGELOG**: flip `## Version 0.6.0 - Unreleased` to
  `Released <date>` at tag time.
- **Docs gate**: `run_docs.sh` (sphinx `-W`) is now clean, but CI's
  `docs_job` builds without `-W`; consider pointing CI at `run_docs.sh` so
  the gates cannot drift apart again.
- **History nuance**: commit `e255b1e` ("harden config init join…") also
  carries the `vm/create.py` half of the storage-containment work whose
  `domain.py` half landed in `7bb413b`; the intermediate commit does not
  build standalone. Cosmetic unless bisecting.
- The sweep's other hard blockers (inert deletion mount guard, EPERM-dead
  shared store, world-readable passwords, principal-scoped credential
  renders, dry-run executing the privileged replay, declined-prompt
  swallows, finish_plan handle leak, recreate containment, locale pinning,
  broken mermaid includes) were all fixed on this branch — see the `fix:`
  commits for the regression tests that lock each one in.
